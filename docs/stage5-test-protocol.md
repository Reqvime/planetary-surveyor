# Этап 5: dry-run scene-node resolver

> F8 не вызывает discovery submit и не меняет сохранение. Probe только читает
> таблицу живых узлов сцены и просит штатный resolver построить discovery data
> во временном буфере.

## Что проверяем

Для последнего объекта, чья карточка появилась в визоре, probe берёт его
позицию как центр. Затем он:

1. проверяет generation, dense index и сохранённый handle каждого узла;
2. оставляет только живые узлы в радиусе 100 метров;
3. вызывает resolver максимум для 1024 ближайших узлов;
4. дедуплицирует полученные Flora, Animal и Mineral;
5. пишет результат в лог без submit.

## Перед запуском

1. Полностью закрыть игру.
2. Оставить AutoScannerPlus отключённым.
3. Использовать одиночный или офлайн-режим.
4. Резервная копия уже существует; этот этап не должен менять сохранение.

## Один контрольный запуск

```powershell
Set-Location -LiteralPath "C:\path\to\No Man's Sky\NMSDiscoveryLab"
.\scripts\deploy.ps1
.\scripts\run.ps1 -BackupConfirmed -PreflightOnly
.\scripts\run.ps1 -BackupConfirmed
```

После загрузки сохранения:

1. Открыть анализирующий визор и навести его на любой объект, пока не появится
   карточка. Новый неизвестный объект для этого dry-run не нужен.
2. Один раз нажать и отпустить F8.
3. Возможна краткая пауза: копируются таблицы сцены и вызывается bounded resolver.
4. Подождать 10 секунд. Повторно F8 не нажимать.
5. Проверить, что счётчики открытий визуально не изменились, и сообщить результат.

Главная строка лога — `SceneResolverSnapshotEnd`. Успех этапа означает:

- `target_resolved=True`;
- `unique_discoveries` больше нуля;
- `unique_type_counts` содержит хотя бы тип наведённого объекта;
- между begin/end нет `SubmitDiscoveryDataV70Candidate`, вызванного F8.

Если игра вылетела или зависла дольше 30 секунд, не повторять запуск.
