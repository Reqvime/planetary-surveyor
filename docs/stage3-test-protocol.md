# Контрольный dry-run этапа 3

> Этот эксперимент только читает один снимок общего списка маркеров. Он не
> подменяет аргументы, не вызывает игровые функции и не регистрирует открытия.

## Единственная гипотеза

Вектор по `cGcScanManager + 0x22F0`, который обходит
`UpdateScannableMarkers`, содержит marker record для настоящего discovery-объекта,
на который наведён анализирующий визор. Если один из трёх подтверждённых handle
совпадёт с `target_node` из `PopulateDiscoveryInfo`, этот контейнер пригоден как
источник загруженных кандидатов для дальнейшего исследования.

## Порядок теста

1. Убедиться, что NMS закрыт и резервная копия сохранения существует.
2. Из обычного PowerShell в корне проекта выполнить:

   ```powershell
   .\scripts\run.ps1 -BackupConfirmed -PreflightOnly
   .\scripts\run.ps1 -BackupConfirmed
   ```

3. Загрузить сохранение на планете с UA `4747691344427360`.
4. Включить анализирующий визор и навести его на неизвестный минерал, но не
   запускать обычное сканирование.
5. Дождаться появления карточки объекта, затем один раз нажать и отпустить F8.
6. Подождать две секунды, отвести визор и штатно закрыть игру.
7. В свежем `logs\pymhf-*.log` найти события:

   ```text
   LoadedMarkerSnapshotRequested
   LoadedMarkerSnapshotBegin
   LoadedMarkerCandidate
   LoadedMarkerSnapshotEnd
   ```

## Критерий результата

- `error=none`, разумные `capacity` и `size` подтверждают чтение vector;
- `target_matches >= 1` доказывает, что наведённый discovery target присутствует
  в списке;
- `target_matches=0` опровергает эту конкретную гипотезу, но не меняет сохранение;
- счётчики Animals/Flora/Minerals обязаны остаться прежними.

Не повторять F8 много раз: одного снимка достаточно. Если игра вылетела, сразу
остановить тест и сохранить свежий лог.
